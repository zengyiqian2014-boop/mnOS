@@kernel
Linux kernel control — kernel INSTRUCTION [OBJECT]

Queries: info, cpu, memory, modules, devices, gpu, irq, log.
kernel sysctl vm.swappiness    Read a kernel parameter
sudo kernel set vm.swappiness=60  Change the runtime value
sudo kernel load MODULE       Load an installed kernel module
sudo kernel unload MODULE     Request unload; in-use modules are rejected
sudo kernel cpu-online NUMBER Bring a supported hotplug CPU online
sudo kernel cpu-offline NUMBER Offline a non-boot CPU when supported
sudo kernel performance balanced|throughput|virtual  Select a TuneD profile

info: kernel release, machine and online CPUs. memory: /proc/meminfo in its
reported units. cpu: /proc/cpuinfo. modules: lsmod. devices: lspci -nnk.
gpu: driver bound to each DRM card; it does not prove acceleration. irq:
/proc/interrupts. log: dmesg; normal Linux restrictions still apply. sysctl
reads the specified key only; a missing/forbidden key reports an error.

Admin operations check root credentials in /usr/sbin/mnos-kernel-admin.
/usr/bin/kernel is not setuid and never elevates by itself. Runtime sysctl
and CPU changes reset at reboot; the TuneD profile persists. CPU hotplug,
module loading and performance controls still depend on platform support.
Use kernel help -cn for Chinese. This entry controls Linux; the original
kernel exposes its own implemented command list via kernel help.

@@editions
mnOS has two editions. Native Edition boots the original C/assembly kernel
and its own GUI. Its Linux window runs an actual Linux kernel and RV64IMAC/LP64
console programs inside an original C software CPU/MMU, with 64 MiB temporary
RAM. It has no guest GPU, floating-point ISA, virtual network adapter or host
storage sharing. It cannot yet run Firefox or VS Code. Guest root is not host root.
Linux Edition uses Debian/Linux/Xfce and mnOS C/C++ management tools. It includes
Firefox, VS Code, development, GNU/Linux commands and CTF desktop applications.
Ordinary applications need no root; changing system state requires authentication.
Each edition has AMD64 and ARM64 media with documented device limits.
No edition claims universal hardware compatibility or security certification.

@@2fa
LOGIN SECURITY: PASSWORD + AUTHENTICATOR
  mnos-security                  Open your account's graphical settings.
  mnos-security --help           Print a short overview without opening a display.
  help -en 2fa / help -cn 2fa    English / Chinese manual.

Enrollment is optional during installation and can be enabled later in Settings.
Scan the locally generated QR code OR manually enter the same Base32 key. Choose
TOTP, SHA-1, six digits, 30 seconds. Enter a valid code to finish pairing. Nothing
is enabled until the encrypted record has been saved. Store the eight one-use
recovery codes elsewhere; they replace a code, never the account password.

Login and disabling the feature require the password first, then a fresh code or
unused recovery code. Reusing an accepted code is denied. Incorrect time can be
recovered with a recovery code. An unavailable service or failed save denies
access to enrolled accounts. ISO sessions do not enroll additional login factors.

Linux password changes: disable the authenticator in Settings first, change the
password, then pair again. PAM currently blocks password changes while enrolled.
Native Edition instead re-encrypts the secret when its own passwd command runs.

ADDITIONAL FACE VERIFICATION (LINUX FULL ONLY)
  mnos-face-preview --enroll     Authenticate, run camera checks, save recovery codes, enable.
  mnos-face-preview --test       Authenticate and test against the saved template.
  mnos-face-preview --delete     Authenticate and delete the saved template.
  mnos-face-preview --help       Print usage without opening the camera.

Face verification is required AFTER the password and any enabled TOTP in PAM.
At the face prompt, press Enter for the local X11 camera window, or enter one of
the eight separate one-use face recovery codes. Keep these codes offline. SSH,
TTY, Wayland and unavailable cameras need a face recovery code. Photos/video
are not saved or uploaded. Ordinary RGB cameras only estimate pose, not trusted
depth; sophisticated replay remains a risk. Disable face verification before
changing the password, then enroll again. Native has no camera login driver.

The Linux Login Process account protects encrypted TOTP files from ordinary
users. Software permissions and encryption at rest do not protect live secrets
from a malicious root or compromised kernel. Native authentication is still a
kernel service, not a separate protected process. Full details and test scope:
/usr/share/doc/mnos/authentication.md

APT — install Linux applications

Examples:
  sudo apt update
  sudo apt install nmap nano build-essential
  sudo mnos apt install nano nmap --without nmap
  apt show nmap
  nmap --version

The Linux edition runs APT on its installed Linux system. It uses the configured
signed Debian repositories; Microsoft VS Code uses its separate signed source in
Full. The package architecture must match dpkg --print-architecture. APT is not
pip; there is no need to install Python to use APT itself. APT shows dependency
and disk-space changes before installation. Run desktop applications as your
ordinary account, without sudo.

mnOS adds --without to its C++ package command: every following name is excluded
from that installation, including dependencies. Existing packages stay installed;
required dependency conflicts stop the transaction. This is a mnos option, not
an upstream apt option. See help updates for selecting Full features.

mnos --uninstall also accepts the mobile-keyboard spelling mnos —uninstall.
It checks all targets before removing anything, and checks APT's dependency-removal
plan. C, CPP, C++, ASM are case-insensitive protected aliases; GCC/G++/Clang,
assemblers and compiler/header packages are protected too. APT still asks before
removing ordinary packages. It does not automatically autoremove dependencies.
This guard belongs to mnos; it is not a restriction on root using other tools.

Inside a supported Linux guest, APT installs INTO THAT GUEST, not into the mnOS
native kernel. Current Native Edition's RV64 BusyBox guest does NOT yet provide
APT, virtual networking, or a Debian userspace. It cannot install Firefox/VS Code
by typing apt. This is an outstanding compatibility feature, not an alias to a
working package manager. The separate Linux Full/Lite editions provide APT now.

If update fails, check network/DNS and UTC time first: ip route; nmcli general;
timedatectl. Do not bypass repository signature or TLS verification. An offline
ISO contains its selected packages, not the entire Debian repository.

Every package name after --without is excluded for this transaction, including
when requested as a dependency. A required dependency conflict stops installation.
Existing packages are not removed. This is not a persistent APT hold. Use plain
package names; options, versions and wildcards are not accepted with --without.
The selected Full installation does not request the all-features mnos-full metapackage.

The Full feature pack restores optional authenticator setup, face verification and
the broader Linux desktop/development/CTF package selection. Optional PAM face
verification includes separate recovery codes. APT downloads dependencies, including Python if a selected
Full tool requires it; the Lite ISO itself has no Python runtime. Your account
and files stay in place. There is no automatic activation of 2FA: open Login
Security and explicitly pair your authenticator using QR or the manual key.

One download directory groups Full, Lite and patches by edition/architecture:
https://github.com/zengyiqian2014-boop/mnOS/tree/resources
update first fetches the signed GitHub Raw catalog, verifies it against the
installed archive key, and reads the latest Linux runtime version. It then asks
APT to install that exact component version. No unsigned index or download is executed.
Catalog: https://raw.githubusercontent.com/zengyiqian2014-boop/mnOS/resources/catalog.json.asc
Packages use a flat APT repository with a pinned signing key and HTTPS:
https://github.com/zengyiqian2014-boop/mnOS/releases/download/updates-stable/
The key is /usr/share/keyrings/mnos-archive.gpg. APT verifies signed InRelease
metadata and payload hashes. Older package assets are retained for explicit
rollback. Failed source refresh stops the command; it does not disable checks.

Rollback covers ONLY the mnOS runtime/auth/full packages. It does not restore
personal files, Debian's Linux kernel or other third-party packages. For those,
use your filesystem backup/snapshot and normal APT version management. Existing
authenticator records must remain compatible with the selected version; do not
remove authentication support while accounts still have a factor enrolled.

The command date still displays/sets time; mnOS does not replace it with an
updater. Package queries need no root. Installing, updating or rolling back
requires explicit sudo, and APT asks before applying its transaction.

These .deb resources are for the Linux edition. The Native Edition cannot use
APT or these packages until its Linux guest gains the required userspace and
network devices. Its current software interpreter keeps guest addresses private;
there is no implemented switch that makes arbitrary Linux binaries native or
removes that memory boundary. Choosing a Linux host means booting Linux Edition.

@@region
Language, region and time
