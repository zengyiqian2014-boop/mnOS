# 原生 mnOS 系统路线

目标是以 `native/` 内的 mnOS 内核构建可独立安装和使用的系统。
系统内核、硬件驱动、进程与内存管理、系统服务、命令行、图形桌面、设置和安装器
由本项目实现。原生运行时使用 C／汇编；本轮构建、测试新增代码使用 C／C++／Shell。
文件管理器和文件系统格式允许复用，保留各自授权与来源。

原生代码使用 GPL-3.0-or-later，源码可获取、修改和再分发。自研范围与自由软件授权
分别记录，不把改名、换主题或重新编译的第三方组件列为原创实现。

## 发布和源码的区别

`v0.4-desktop-preview.1` 新增原生图形安装器与桌面，安装到 GPT 磁盘，移除 ISO 后直接
启动原生 GUI，包含文件浏览、编辑器、菜单、终端及个人设置。双架构测试覆盖安装、
登录、文件和设置持久化；[配置与现有限制](DESKTOP.md)。桌面目前仍为内核内服务。

`v0.3-native-preview.1` 是通过双架构 CI 的原生内核启动介质，发布固定于提交
`5fc4544e28a74442ddc2b9437608adf97e053c9e`。它已有多进程、权限隔离、MNFS 和图形终端。
发布物来自该提交的实际测试产物，附有哈希、源码标识和日志；它尚不是完整安装系统。
新增用户态文件接口进入 `v0.3-native-preview.2`，并由新的双架构回归验证。
发布流水线只接受成功 CI 的原始产物，发布时校验产物哈希与源码提交。

旧 `v2.0-installer-preview.2` 仍是 Debian/Linux/Xfce 应用环境，并有独立的早期原生内核
入口。它不作为新原生系统的运行基础。Firefox、VS Code、CTF 工具尚未移植到原生 ABI。
这些应用的来源和兼容状态将独立记录，不能以“自研应用”标注第三方软件。

## 目前已经实现

| 部分 | 实现与边界 |
| --- | --- |
| 内核 | x86_64、ARM64 原生 C／汇编，独立地址空间、定时抢占、动态进程、休眠与退出回收 |
| 内存 | 稀疏物理页分配器，物理地址空间上限 64 TiB，并受 CPU 地址宽度约束 |
| 多核 | 动态 CPU 发现和启动；应用目前在启动 CPU 上调度，尚无迁移和 NUMA 调度 |
| 文件 | 自研 MNFS，CoW、CRC32C、64 位稀疏文件、目录和快照；原生程序可读写自己的目录 |
| 用户边界 | 普通用户与 root 分离，受保护的账户记录，进程创建时捕获 UID，切换账号撤销进程 |
| 图形 | 原生多窗口、应用搜索、文件浏览、文本编辑、终端及设置；当前服务运行于内核内 |
| 安装 | 原生 UEFI 图形安装器，GPT/FAT32 引导分区 + MNFS 数据分区，双架构脱离 ISO 启动验证 |

主线用户态文件接口支持创建、读取、写入、查询、截断、删除和创建目录。它检查完整
请求和指针边界，拒绝写入 RX 代码页，以捕获的进程身份核对当前会话。用户路径须是
规范绝对路径，禁止通过 `..`、重复分隔符或其他用户目录绕过权限。磁盘只读、I/O 错误
和校验失败都向应用返回错误。当前调用同步执行，每次最多 4 KiB；异步 I/O 尚未实现。

## 接下来的可验收工作

1. 原生应用环境：扩大可执行映射，补目录枚举、文件描述符、进程等待、管道、输入与
   IPC，实测权限隔离和资源回收；以此实现独立用户态 shell、编辑器和系统服务。
2. 原生设备层：PCI／VirtIO 共用设备模型、块设备与网络队列、中断和设备重置；先测
   虚拟机，再逐个记录实体控制器。AHCI／NVMe、USB、Wi-Fi、音频和加速 GPU 仍需实现。
3. 原生桌面：窗口合成、输入事件、字体和工具启动协议。应用列表、系统设置、内核设置
   和显示设置接入同一桌面，并在真实用户态运行。
4. 原生安装器已接通空盘安装、移除 ISO、磁盘启动、登录和持久化。下一步扩展磁盘驱动、
   既有分区安装、升级与恢复；逐项新增实体机器验证。

AMD64 与 ARM64 共享系统接口与测试语义，体系结构代码单独实现。测试报告标出具体
固件、CPU、控制器和显示设备。Apple Virtualization.framework 与 QEMU 是不同平台，
需要分别验证，不能从某一次 QEMU 成功推断所有虚拟化平台和实体硬件均兼容。

## APFS 和外部组件

APFS 是候选兼容格式，目前未实现。接入时先验证格式识别和只读解析，拒绝不支持的
加密、压缩或格式特性；写入支持必须经过断电、损坏输入、空间耗尽、回滚及可重复的
跨实现读写测试之后再开放。现有 MNFS 不改名为 APFS，也不把 APFS 的特性直接算为
mnOS 已支持。UEFI 启动分区使用 FAT，不决定系统数据分区必须使用 FAT。

新桌面安装路径在 AMD64 和 ARM64 均采用本项目 UEFI 加载器。旧 BIOS 诊断介质仍使用
GRUB；构建工具链与 Noto 字体为外部组件，来源与许可保留。用户态桌面服务仍需完成，
CPU 固件和设备固件的来源也需单列。

安全、速度和稳定性按结果推进：边界／恶意输入测试、内存与存储故障注入、双架构启动
和持久化回归是每次发布的基础；性能比较必须给出设备、负载与可复现数据。现有功能
测试不代表完成安全认证，也不代表已优于 RHEL/Linux。
